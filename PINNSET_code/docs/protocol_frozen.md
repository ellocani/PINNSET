## 실행 순서

### 1단계 — 평가의 전제 확인: K01 → K02 → K03

- 데이터 키·예측 시점·라벨 해석을 고정합니다.
- 전체 전처리를 학습 내부로 넣은 시간 순서 검증을 구성합니다.
- 시험 사건 전체가 학습과 분리되는지 확인합니다.

종료 기준: 설명되지 않은 행 문제, 미래 정보 참조, 학습/시험 공유가 없음. 확인할 수 없는 라벨·시점은 제한 사항으로 남깁니다.

### 2단계 — 성능의 신뢰성 확인: K04 → K05 → K06

- 평가불가·보류를 포함한 전체 운영 결과와 안정기 결과를 분리합니다.
- 같은 검사 예산에서 기존 모델들과 비교합니다.
- 사건별 실패와 불확실성을 함께 보고합니다.

산출물: 제품별 공통 비교표, 전체/안정기 운영표, 사건별 결과와 불확실성.

### 3단계 — 프로젝트의 차별화 근거 확인: K07 → K08

- FLR의 예측 기여, PINN의 처방/요청 역할, A/B/C 원인 설명 범위를 확인합니다.
- 실제 관측량과 요청 엔진의 식별성 계산을 연결합니다.

산출물: 물리 근거·가정·한계 표, 후보 측정별 식별성 검산과 조건부 요청 판단.

### 4단계 — 최종 주장 정리

별도 검증 항목을 추가하지 않고 위 결과에 따라 보고서의 핵심 문장만 ‘유지 / 조건 추가 / 표현 완화 / 수정’으로 정리합니다. 결과가 바뀐 표와 연결 문장만 갱신합니다.

최종 산출물: 8개 검증 결과표, 필요한 경우 수정 전후 성능표, 최종 주장과 제한 사항.

## 판단과 기록

- 누설·중복 평가·잘못된 분모는 수정해야 합니다. 원하는 성능이 나오지 않아도 검증 방법을 바꿔 수치를 유지하지 않습니다.
- 실제로 가능한 초기 검사 정책을 명시합니다. 정책이 미확정이면 전체 운영 결과는 그 정책에 조건부로 보고합니다.
- 수치 허용오차·사건 분할·검사 예산·재표집 방식은 결과를 보기 전에 고정합니다.
- 자료 부족은 ‘미확인’으로 기록하고 관련 주장만 제한합니다. 나머지 가능한 검증은 계속합니다.
- AUC/F1에 임의의 합격선을 만들지 않고 공통 조건의 개선량·불확실성과 주장 범위를 평가합니다.

각 항목은 **방법과 대상 → 결과와 불확실성 → 판정 → 유지/수정할 주장**의 네 칸으로 기록합니다. 판정은 통과 / 조건부 통과 / 수정 필요 / 자료 부족으로 구분합니다.

현재 상태: **아래 실행 프로토콜을 고정하고 핵심 검증을 진행합니다.**


## 실행 프로토콜 — 2026-10-04 고정

결과를 보기 전 분할·정책·예산을 다음과 같이 고정합니다. 원본 v9 코드·모델·CSV는 수정하지 않습니다. 검증용 코드는 원본의 기준 생성·이탈·보정 함수를 재사용하되 평가 범위를 바로잡습니다.

| 묶음 | 항목 | 실행과 판정 | 산출물 |
|---|---|---|---|
| A: 평가 기반 | K01~K03 | 키·중복 충돌·LH/RH 샷 집계 및 병합 검산. 각 연속 가동 구간 시작보다 앞선 라벨/무라벨만 사용한 forward 평가. 결함 간 30분 기준 사건이 여러 구간에 걸치면 구간을 하나의 블록으로 묶은 leave-block-out 평가 | 데이터 검산 JSON, fold별 자료 시각/건수, 분할 겹침 검사, 부품별 예측 |
| B: 성능 | K04~K06 | 전체 부품·보정층 준비 후·점수 가능 부품을 각각 평가. 동일 fold·부품·CN7 5%/RG3 50% 예산에서 상수/PINNSET/로지스틱/HistGB/Isolation Forest 비교. 사건 블록 단위 2,000회 bootstrap | 운영 혼동행렬, 공통 비교표, 블록별 결과, AUC 및 검출 차이 구간 |
| C: 핵심 근거 | K07~K08 | 동일 fold에서 FLR 제외 모델 한 번 비교. 기존 PINN 독립 검산 재사용. 기존 처방 운전점의 PINN 입력 영역 점검. C 관측식의 해석 미분과 rank 검산. A 대표점의 0.025/0.05/0.1 K 중심차분 비교 | FLR 기여표, 물리 주장 판정, 관측식·식별성 검산 |

- forward: 제품별 gap > 300초인 기존 구간 순서 사용. fold 시작 시점 미만의 자료만으로 양품 레시피 지문, 무라벨 lot 선별(최소 30행), 문·척도를 계산합니다. 기준 생성 또는 불량 포함 보정 학습이 불가능하면 평가불가로 남깁니다. 라벨은 과거 구간 종료 후 모두 확보된다는 조건부 가정입니다.
- 기준 갱신: 각 fold에서 그때 확보된 자료로 과거 샷을 다시 계산해 보정층과 상태를 구성합니다. 현재 fold의 미래 샷이나 라벨은 이 과정에 쓰지 않습니다. 실제 온라인 배포의 비동기 갱신 시험은 범위 밖입니다.
- 독립 사건 평가: 결함 간 시간차 > 30분을 별도 사건으로 정의합니다. 한 사건을 공유하는 가동 구간을 합친 블록 전체(양품·불량·LH/RH)를 보류하고 각 시험 구간 앞뒤 5분도 학습 라벨·무라벨에서 제거합니다. 학습 이탈 계산에서도 시험 샷을 제거합니다. 시간상 미래의 다른 블록은 이 후향 일반화 평가에 사용할 수 있으며 forward 결과와 구분합니다.
- 비교 모델: 기존 E2 파라미터를 그대로 사용합니다. 추가 튜닝·F1 임계값 탐색은 하지 않습니다. 학습/시험은 해당 fold에서 PINNSET이 점수를 낼 수 있는 동일 부품을 사용합니다. 이상탐지에는 기존과 같이 RH를 입력하지 않습니다.
- 예산: 구간 내 점수 순위로 가까운 정수의 검사 수를 배정합니다. 같은 seed=20261004의 고정 난수로 동점을 깨고 모든 모델에 같은 tie key를 씁니다. 이는 검사 예산 비교용 후향 순위이며 실시간 백분위 임계값의 운영 성능과 구분합니다.
- 전체 운영 정책: 점수 부품은 CN7 D≥5/RG3 RH 우선검사, 보류·평가불가는 전수 대체검사로 가정합니다. 이 가정하의 검출은 검사로 선정된 불량 수이며 검사가 항상 불량을 찾아낸다는 현장 성능은 검증하지 않습니다. 예산 비교에 대체검사 비용을 숨기지 않고 별도 운영표에 보고합니다.
- 재가동: 실제 정지 후 재시작 구간만 사용하고 자료 최초 구간은 제외합니다. 고정 3/5/10샷 분리와 재가동 10샷 내 D≥5 분리, 준비 불가도 분리하는 보수적 정책을 같은 전체 샷에서 대조합니다. 분리와 폐기는 구분합니다.
- 불확실성: 한 사건을 공유한 구간을 합친 블록을 복원 추출합니다. 고정 예측의 조건부 bootstrap이며 학습 재실행/새 사건 수집/선택 편향 보정이 아닙니다. 양·음성 중 하나가 없는 표본의 AUC는 계산하지 않고 유효 반복 수를 표시합니다.
- 판정: 키/조인 손실·겹침·미래 참조·독립 검산 차이 허용 0(부동소수점 확률 및 이탈 비교 1e-10). AUC/F1에 임의 합격선은 두지 않습니다. 개선 주장은 공통 비교 및 불확실성 범위에 맞춰 유지·조건 추가·완화·수정합니다.
- 초기허용불량: 기본은 원본 N 라벨로 포함합니다. 운영표에 해당 라벨 10부품 제외 결과도 함께 냅니다. 물리 불량 종류·검사 기록 시각·실제 센서 위치·수지 등급·설정 상한은 자료 부족 여부를 명시합니다.
